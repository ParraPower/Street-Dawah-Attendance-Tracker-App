# Project documentation topics

Before generating the documentation comment, define the key topics that should be covered for the AuthApp project. Below are recommended topics and concise descriptions you can use directly in documentation.

1. **Project overview**

AuthApp provides an authentication and authorization API for other services (for example, the Attendance API).

2. **Architecture**

Domain-driven design: code is organized into domains and modules. Modules contain controllers, services, DTOs, and middleware.

3. **Core components**

- Entities:
  - `UserEntity`: represents application users.
  - `ClientEntity`: stores client-credentials entries (client credentials flow).
  - `KeyEntity`: stores asymmetric key pairs used for signing and verifying JWTs.
- Modules:
  - `auth`: authentication and authorization (controllers, services, middleware).
  - `user`: user management (controllers, services, DTOs).

Note: modules may contain DTOs, controllers, services, and middleware.

4. **Authentication flow**

For users: register, then call `POST /auth/login` to receive a JWT. The system also supports client credentials for machine-to-machine authentication.

5. **Directory structure**

- Root level:
  - `src/`: Main application source code, organized into domains, modules, and shared components.
  - `scripts/`: Utility scripts for Docker deployment and database migrations (e.g., `docker-run.ps1`, `generate-migration.ps1`, `run-migration.ps1`).
  - `docker-compose.*.yml`: Docker Compose configuration files for development, local, and production environments.
  - `instructions/`: Documentation and context files for development tools.
- Under `src/`:
  - `domains`: business entities and domain logic (should be independent of tooling or infra).
  - `modules`: feature implementations (controllers, services, DTOs, middleware).
  - `core`: shared base classes and request/response abstractions.
  - `data`: database data-source, TypeORM setup, and repositories.
  - `mapping`: entity/DTO mapping profiles and AutoMapper configuration.
  - `security`: JWT, key cache, token blacklist/whitelist, and auth guards.
  - `types`: project type augmentations and custom type definitions.
  - `dtos`: DTOs (consider moving module-specific DTOs into their module folders).
  - `config`: environment and configuration loaders (see [config/env.ts](config/env.ts#L1)).
  - `migrations`: database migration files generated by TypeORM.

6. **Key dependencies**

- `TypeORM` — database ORM and migrations
- `express` — HTTP framework
- `jsonwebtoken` — JWT creation and verification
- `bcrypt` — password hashing
- `automapper` (or AutoMapper binding used) — entity/DTO mapping

7. **Configuration**

Uses `cross-env` and `.env` files for multi-environment configuration. See [config/env.ts](config/env.ts#L1) for the environment variables currently read by the application.

8. **Error handling**

Centralized error handling is not yet implemented. Recommended approach: a global error middleware that normalizes errors into a consistent HTTP response format, structured logging, and optional integration with an error-reporting system (Sentry, etc.).

9. **Security considerations**

- Authorization uses scopes defined in [modules/auth/scopes.ts](modules/auth/scopes.ts#L1) and enforced via guards/middleware.
- Key management: store asymmetric keys securely and rotate when necessary; token blacklist/whitelist entities exist under `domains/tokens`.

10. **Testing strategy**

Tests should live under `__tests__` with a mirrored folder structure. Use `jest` for unit tests and `msw` for mocking external HTTP calls.

11. **Migrations**

Database migrations are managed with TypeORM and stored in the `migrations` folder.

12. **Next steps / TODOs**

- Implement centralized error handling and logging.
- Consolidate `core` responsibilities into `domains` or `modules` where appropriate.
- Move module-specific DTOs from `dtos` into their respective module folders.

13. **Migrations**

- scripts: scripts folder at root contains various powershell scripts which are run via npm to action schema migration generation, rollback and application
- library: refer to `TypeORM` in `Key dependencies`
